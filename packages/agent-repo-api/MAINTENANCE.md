# Skill maintenance API v1

`./maintenance` is a host-local optional provider registry. Canonical source is copied into each standalone plugin; global symbols coordinate registry, errors and in-flight journal admission across bundles. Providers register `apiVersion: 1`, a stable namespaced ID, owner token, read-only `snapshot(context)` and `run(context, input)`. Disposal removes only the registration generation it owns. `agent-repo.main-skill` is reserved for AgentRepo.

Snapshots declare `kind` (`cli` or `generated-skill`), `ownerLabel`, actual human-readable `scope`, state, optimistic `revision`, `observedAt`, associated skills and allowed actions. Optional `versions.current/available`, policy, whitelisted diagnostic fields and bounded body preview support generic presentation. Provider scope is not inherited from the selected project. Missing or unsupported capabilities are explicit; do not infer external CLI dependencies from names. Loading a provider or listing skills grants no invocation permission.

The management boundary validates trusted Agent/session ownership and operator scopes. UI confirmation is not authorization. Provider run methods must recheck allowed actions, settings whitelist, scope, version and domain-specific policy. Never accept arbitrary commands, paths, environment variables, credentials, or business payloads. Configuration mutations use public host APIs and preserve unrelated fields. Providers own installation, authentication and persistence; AgentRepo only aggregates.

`createMaintenanceOperations` durably admits an idempotent operation before background work. Identity combines Agent, session and request UUID; input digest binds action, expected revision and settings. Find prior admission before checking current revision, so a successful original request can be safely queried after the state changes. In-flight tasks remain visible across module replacement; records left running after restart are `unknown`, with no automatic replay. Journal metadata includes action, timestamps, source Agent and safe error codes, never raw errors or credentials. Providers retain their domain locks and cancellation logic; the journal does not replace cross-process CLI or publication locks.

History queries do not mutate state. New completions may prune ended operations older than 30 days while retaining at least the latest 100. UI returns the latest 20. Idempotency retention is therefore bounded; clients must not intentionally reuse expired UUIDs.
