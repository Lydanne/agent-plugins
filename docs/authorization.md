# Worker 执行权限

## 一期边界

本期只管理 Worker 权限。OpenClaw 继续管理 Main 的能力与会话权限；不注册 Main 工具发现过滤，不限制 Main 技能目录、普通工具调用、人员补采或定时触发。Main 向 Worker 提交任务之后，由 Worker 按可信原请求人检查任务准入和执行权限。

agent-repo 提供权限事实、管理界面与判定服务；agent-worker 承担任务及实际执行检查。权限库为独立的 `.runtime/authorization.sqlite`，单向引用实体 ID，不向实体库增加权限字段或反向依赖。不修改 OpenClaw。

## 权限模型

基础动作是 discover/read/create/update/delete/execute/transfer/delegate/grant。读写与原子性、可恢复性、幂等性、外部影响、敏感度分别保存；原子性和可撤销性不是同一属性。多项要求必须全部满足，明确禁止优先，无允许依据则拒绝。

预置管理员组 administrator、内部组 internal、外部组 external，不自动绑定任何人。管理员默认接纳已核验且具备拦截的能力，内部默认接纳普通、无外部影响的只读能力，外部默认无授权。宽泛执行资源仅能显式授权。执行权限组不会自动授予管理中心的 operator.admin 权限。

组织、部门、个人通过权限侧绑定表关联权限组，部门支持直属成员或包含下级部门。服务端根据可信账号、来源和实体关系解析权限，不从模型正文接受身份或权限结论。未知、过期、不完整或冲突的身份关系不能授权。

## 资源和新增资源默认授权

扫描工具、技能及已注册 CLI 元数据，保留稳定 ID、提供方和定义版本。名称、描述不能证明只读或可撤销。新增资源先待核验；已有专用适配器的资源按适配器合同处理。

普通扫描工具及工具型 CLI 子命令，可由 operator.admin 编辑分类，再显式核验启用通用调用检查。需明确操作性质、外部影响和敏感度，并确认分类覆盖全部行为。核验记录人、时间和定义指纹；分类变化或扫描到新定义后失效。核验与默认授权生成同事务完成。通用检查不提供沙箱、自动回滚或撤销实现。

通用读取要求 execute/read，写入要求 execute/create/update/delete，外部影响要求 transfer。混合行为要求全部动作且仅显式授权。CLI 子命令优先于整个工具，未知子命令和同名多提供方拒绝；停用子命令不能退回父工具授权。专用适配器的拒绝或歧义不能被通用规则覆盖。

默认授权绑定策略版本和资源版本。修改默认策略不追溯改变已有授权；管理页支持预览和显式重算。规则使用草稿发布和乐观版本检查。参数条件检查真实调用参数，所有条件共同满足；模拟不会执行工具。

## 已接入的 Worker 检查

- 受理时保存原任务权限上限；启动、恢复和后续调用结合当前权限重新检查。
- 子任务继承父快照，不能因新增授权扩大；主体变化或父快照缺失拒绝。
- 任务绑定的插件 CLI 使用服务端签发的原 job 身份和调用范围，目录与参数说明按 discover 权限过滤；调用前执行权限检查，宿主策略改写参数后按最终参数再次鉴权。
- Worker 技能目录按授权子集及已扫描版本过滤，独立工作区映射到实际技能路径。
- App Server 与 JSONL 新建、恢复及技能刷新时关闭原生技能目录自动发现、技能说明自动注入和内置技能；技能上下文由 Worker 提供。JSONL 拒绝会覆盖这些配置的模板参数。保留项目规则和全局用户说明。此设置不阻止宽泛文件工具读取技能，也不能删除旧会话已经保存的内容。
- App Server 在创建或恢复会话前读取生效配置，逐项关闭配置中的原生 MCP 服务，插件调用使用原任务绑定代理；配置无法核验则拒绝开始任务。不向模型返回连接配置。此措施尚不覆盖 JSONL 原生 MCP、插件动态添加的服务或其他原生执行入口。
- 人员远程补采在请求前及写库前检查，继续使用原 Worker 权限上限；本地读取与补采写入分开。
- Worker 结果交给交付桥前检查 transfer 权限。
- 兼容 person_lookup 自动协作按原 job 检查人员查询权限；读取前、缓存结果回传前均重新检查。拒绝的人员查询不能经完成桥转交 Main 代查。

宿主可信工具策略只处理带有效 Worker 调用范围的请求，普通 Main 调用直接交由 OpenClaw。已知 Worker CLI 请求丢失范围时拒绝，不能降级为 Main。Worker 代理调用的权限归属取决于原 job，不取决于检查代码运行在哪个进程。

## 仍需完成的执行边界

执行器必须保留现有 Codex CLI 登录态，不要求另配模型 API 端点或凭据，不复制、迁移或替换登录文件。新建 App Server 会话注册 `worker_plugin` 动态工具，将发现、描述和调用交给原任务绑定的插件代理；恢复会话沿用 CLI 保存的工具声明。旧会话不会因恢复自动增加动态工具。调用核对当前 thread/turn、重复调用 ID 和取消信号，技能刷新阶段拒绝调用。动态工具不代替原生工具隔离，因此不改变现有任务准入。

可选离线协议测试通过 `WORKER_CODEX_CLI=/absolute/path/to/codex pnpm test:codex-permissions` 运行，使用独立 HOME、合成配置和本地假模型服务，不读取现有登录态。2026-11-04 对本机 `0.166.0-alpha.6` 的 5 项测试确认：只读沙箱仍暴露原生命令；禁用相关功能并固定模型元数据后，合成原生命令被拒绝；空 MCP 配置不能清除继承的服务，须逐项禁用；模型元数据可另行注册 apply_patch。这些结果仅适用于测试二进制和配置，不证明生产执行器已完全隔离。

另有 2 项实际 App Server 协议测试调用生产使用的 Worker 适配器，验证动态工具请求进入宿主回调、结果回传模型，以及重启 App Server 后恢复原 thread 时保留工具声明并使用新宿主回调。合计 7 项离线测试；未使用真实账号或远程模型，也未验证生产配置的全部能力隔离。

技能上下文另有 4 项实际 CLI 测试：原生工具关闭后技能说明仍可能自动注入；关闭技能发现及项目说明后，全局用户说明仍保留；Worker App Server 的新建及恢复会话均不追加临时未授权技能说明，但保留项目规则；Worker JSONL 生成的实际命令同样不追加技能目录。离线协议测试共 11 项。旧会话历史与文件读取边界仍需处理，继续原会话不代表历史内容已被清除。

另有 2 项实际 App Server 测试验证配置中的 MCP 在新建及恢复时不启动，并验证合成模型即使发出未声明的原生 MCP 调用，也会被 CLI 拒绝而不转交宿主代理。协议测试合计 13 项；仍不构成所有原生工具路径的完整隔离验收。

当前外部执行器仍可能使用不受限的 Shell、文件、网络和代码执行；这些并未全部经过受控插件 CLI。技能目录过滤不是文件隔离，任务准入不代表逐次操作检查。

目前 run/reply/steer 仍保留要求全部动作的保守准入，尚未完成“普通任务准入”和“宽泛宿主执行”的拆分。不得在实际执行通道收敛前，仅放宽此检查而声称只读 Worker 已安全可用。后续需接入受控执行方式、验证不可绕过的操作限制，并核对 Worker 请求 Main 代理执行的路径。

一期最终验收要求：Main 正常功能不受新策略影响；只读用户能使用 Worker 做只读任务；Worker 内部操作与技能分别授权，不能借 Shell、其他入口或 Main 代理绕过；恢复、子任务和撤权保持一致。当前实现尚未达到全部验收条件。

执行器接口核对（2026-11-04）：[Codex App Server](https://learn.chatgpt.com/docs/app-server) 提供动态工具调用及文件沙箱设置，可用于接入 Worker 权限代理；但不能据此推断所有原生能力都会经过动态工具。[Codex Hooks](https://learn.chatgpt.com/docs/hooks#tool-coverage) 明确说明托管工具不走本地工具钩子、部分特殊路径可以跳过钩子，write_stdin 也不会再次触发 PreToolUse。因此单独添加 PreToolUse 不满足本项目的完整拦截要求，不能作为放宽任务准入的依据。下一步需要验证受控执行器的完整能力清单与不可绕过的隔离，再接入权限代理。

## 验证与交付边界

使用隔离状态和合成身份运行 Node、UI、浏览器测试。本次 Worker 范围调整已通过 pnpm typecheck、pnpm build、pnpm test，以及 5 项权限页面浏览器检查。没有生产部署或真实渠道端到端验收授权；代码提交和测试成功不代表已经上线。
