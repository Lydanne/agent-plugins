# Worker 项目目录策略

## 固定职责

| 目录 | 用途 | 分支与写入 |
| --- | --- | --- |
| `projects/<项目>` | 共享的本地代码和技能资料副本 | 保持 projects.json 登记的默认分支；Worker 强制只读 |
| `workspace/<项目>-<编号>` | 需要文件写入或切换分支的任务 | 宿主分配独立 clone；在原授权内写文件、切分支和交付 |
| Worker 私有状态目录 | 宿主生成的任务报告、审计与调度状态 | 宿主管理，不写入共享源码副本 |

默认分支以登记配置为准，不由任务文本或远端 HEAD 猜测。目录策略适用于使用 AgentRepo 项目绑定的新执行；旧 fixed-cwd 安装保持兼容。管理员对仓库的直接维护不是普通 Worker 任务。此实现不修改文件系统所有权，也不把执行器沙箱当成插件工具的完整隔离边界。

## 受理与执行

1. Main 明确项目和范围。纯查询、日志与源码分析可省略 useWorkspace；写文件、导出、生成本地产物、安装依赖或需要检出其他分支必须传 `useWorkspace:true`，并保留原业务授权限制。
2. 宿主本地核对登记、独立 Git 根、默认分支、工作树和有效技能。脏副本或分支不符时保留现场并拒绝准备，不自动 stash、reset、切换或提交。
3. 项目绑定的 Worker 通过宿主生成的 Codex 目录权限配置执行；projects 和其他工作区保持只读，当前 workspace 才按原权限允许写入。模板不得覆盖该边界。结果内联返回，宿主在私有状态目录 `reports/<jobId>` 保存报告。工作区任务必须完成分配才可执行，不回退 projects；执行权限仍受管理员原配置约束，管理员 read-only 不会被提升。
4. workspace 内允许按任务需要切换分支；仍校验分配归属、路径、远端和技能版本。旧分配保留原分支约束。更改任务规范/技能时仍需要新的有效执行范围，不用切分支绕过校验。
5. 池满沿用原 job 等待；补充和恢复沿用原分配；现场保存、原槽位恢复、发布与部署授权遵循既有 workspace 协议。

目录要求不会自动授权 shell、文件工具、外部 API 或发布操作。宿主使用 Codex 公开的命名权限 profile 限制原生 shell 和 apply_patch；JSONL 使用每轮唯一、0600 的配置层，app-server 通过 RPC 指定权限并核对实际生效回执。保留原 CODEX_HOME 的认证和会话位置，不覆盖原 config.toml，不把 provider 凭证写进命令行；每轮结束清理本轮临时配置。项目本地配置不能扩大执行权限。旧 CLI、不支持的自定义启动包装或无法安全保留的配置在业务执行前明确拒绝。

当前 workspace 的文件与 Git 元数据按原权限放开，projects 和邻居 workspace 保持只读；软链接不能绕过。已有多链接文件额外标记为只读，防止写工作区硬链接时改变外部同一 inode；不拆链或修改文件内容。执行器本体照常保存会话，模型工具不获得共享 CODEX_HOME 写权限；临时存储必须位于安全的私有运行目录。启动程序、PATH、运行目录及本地 MCP 环境也需通过目录边界校验。

管理员原有 read-only/workspace-write 等更严的约束继续保留，不能通过目录策略提升权限；其原有 Git、命令网络限制也仍生效。原完全访问查询保留已有网络能力，文件仍受目录约束。技能刷新保持只读并禁用命令网络，模型 provider 的正常连接不因此被切断。本地 MCP 命令单独使用官方 sandbox 保护；启用但无法保护的 hooks 和沙箱外 notify 命令在业务执行前拒绝。宿主代理的外部插件和远端 MCP 调用仍按原权限系统校验，不能把本地工具沙箱当成远端服务的完整隔离边界。

工作区计划在同一读取租约内捕获：项目布局读取已受理的父仓提交，子仓使用各自捕获的实际 HEAD，不能被父仓旧 gitlink 覆盖。相同槽位中不同任务的同名分支由各自检查点私有引用保护；仅当当前分支尖端精确匹配另一个已完整保存、已释放的任务凭据时才恢复原分支，否则保留现场并阻止恢复。历史列表读取分配状态不写入池，不以缺少绑定的旧记录冒充可安全恢复。

## 异步更新

skills、Worker 范围准备以及普通入站项目准备只读取本地副本并排队更新；Agent 角色仓库原有同步与提示词门禁不变。返回 `synchronization.mode=background,state=queued` 仅表示已排队。队列按项目合并，一分钟冷却，服务每秒检查；新请求可在失败后再次触发。不是常驻逐项目拉取，也不保证每个任务读到远端最新提交。

后台更新前重新核对登记，只做安全快进，并更新声明的业务子仓库/wiki。子仓库保持配置默认分支，detached 或其他分支不自动纠正。同步分为 fetch 和工作树变更两阶段：fetch 保留串行写锁，但通过绑定锁身份的阶段标记允许读取现有工作树；进入 merge/checkout 前移除可读标记并重新检查读取租约，有读者就延后更新。Worker 执行、Main 提示词使用及 workspace 计划捕获都受租约保护。确认进程已退出的遗留写锁不再永久阻塞读取；锁状态不明或旧协议仍保守处理。失败、结束和插件停用释放所属租约，不释放其他任务的租约。

网络、认证、冲突等失败写现有仓库诊断日志，不让后台异常打断已受理任务；不会声称已取得最新代码。显式 sync 和既有定时维护继续返回实际同步结果，也遵守读取租约。运行前允许仅代码发生安全快进；技能或规范发生变化时仍阻止使用旧快照执行。

## 发布与迁移

agent-repo 与 agent-worker 需配套发布共享读取租约协议。发布前核对 projects 默认分支、工作树、子仓库及 workspacePool；不自动清理历史源码产物或切换现存分支。角色规则中要求 Worker 在 projects 写 `.tmp` 的旧约定需同时调整为 workspace。正在运行的旧执行器不能靠热加载补上读取租约，因此首次启用后台更新应等旧任务安全结束，或先停用自动同步，完成核对后再启用；禁止通过重启取消活动任务。本文实现与测试不代表生产迁移已完成。
