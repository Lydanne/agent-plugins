# AgentRepo 审计

管理中心新增独立“审计”模块。相同视图支持全局查看，以及按功能、对象、发起人 ID、动作、结果、起止时间筛选和分页。定时任务详情的“修改日志”固定当前计划 ID，管理编辑器可展开完整修改日志；实体详情、实体模块、工作区配置、技能模块和日志模块提供相应入口。

## 记录内容与身份

统一记录包含审计 ID、Agent、功能、对象 ID/名称、动作、时间、原请求 ID、发起身份、执行入口、请求修改内容、修改前后快照和逐字段差异。创建、修改、暂停、恢复、删除、立即执行均保留记录，删除计划不会删除其审计。时间、时区、名称、启停状态、投递位置等变化均可比较。

群内 `agent_schedule` 以本次可信真人来源生成修改人 ID、渠道账号、群和请求消息 ID；不是读取原计划创建人充当修改人。模型参数不得覆盖 actor、executor 或消息依据。控制面板以宿主已认证连接的 `connId` 标识操作人，当前公开上下文未提供实名，因此明确显示“未提供实名”，不借用原请求人姓名。实体存储旧审计只提供执行器身份，明确标记真人指派资料未记录。

状态区分 `pending`（处理中或中断待核验）、`accepted`（异步操作已受理，执行结果另查）、`succeeded`（管理操作完成）、`failed` 和 `unknown`（结果待核验）。原生调度写入不确定时不能声称成功或自动重放。未知结果中的快照表示适配层保存状态，不证明原生配置或业务执行成功。

## 接口

`projects-audit` 是 `operator.read` 会话动作，Agent 从受信上下文解析，不接受 payload 中的 Agent、路径或身份。参数：

```json
{"feature":"schedules","targetId":"<计划ID>","actorId":"<发起人ID>","action":"update","status":"succeeded","from":1793289600000,"to":1793376000000,"limit":25,"offset":0}
```

所有筛选可省略。`from/to` 为毫秒时间戳。`limit` 默认 50，范围 1–100；全局 `offset` 上限 10000，更多历史请缩小时间或对象范围。筛选先于分页；响应含 `records/total/nextOffset`。来源未加载时在 `unavailable` 中列出，读取失败不伪装为零记录。

群内模型工具另提供 `agent_schedule action=audit,id,limit,offset`，只读当前请求人、账号、群和会话代际拥有的计划。查询授权与 get/history 相同，不开放全局跨群资料。

## 持久化与覆盖范围

- 群计划和系统同步计划审计分别存于其现有私有 SQLite 的 `audit_events` 表。变更前先持久化 pending 意图，取得管理结果后写入状态和差异；重启后的 pending 不推断为成功。计划稳定 requestId 重试复用原审计。
- 面板的工作区设置、人员更正/删除、同步受理、技能维护和日志清理写入 Agent Repo 下 `.runtime/audit/audit.sqlite`，由服务器选择目录，不进入 Git；人员字段和配置字段按白名单投影，不复制整个请求、凭证或错误正文。
- 已有实体/关系的事务审计从 `graph_audit` 适配到统一查询，保留来源执行器。它与面板的指派受理记录是两个阶段；实体库的访问范围沿用当前 Agent 绑定仓库，与原实体读取接口一致。
- 旧计划 operations 首次加载时幂等导入为旧版审计，不补造当时未保存的实名、指派消息或快照。上线前没有记录的操作不能追溯；创建人不等于后续修改人。
- 清空普通日志不清空审计；没有审计删除/修改的管理接口。数据库及私有目录采用 0600/0700。此版本不提供对本机管理员篡改文件的密码学证明，也不声称能审计插件外直接修改 SQLite、配置或原生 cron 的行为。

新功能应在实际变更边界使用 `auditBegin/auditFinish`，传服务器解析的身份、对象和字段投影；现有实体事务保留原事务审计。不得只靠浏览器点击日志判断变更成功。生产部署和真实群验收单独进行；隔离测试不向真实计划写入。
