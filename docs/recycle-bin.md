# AgentRepo 统一回收站

管理中心所有模块右下角提供“回收站”悬浮入口。软删除后，资源从普通列表、统计和常规查询中隐藏，回收站支持功能筛选、搜索、分页、内容摘要与恢复。当前接入已有删除能力的群计划、系统同步计划、人员、来源实体以及仓库日志清理；Worker、技能、项目和工作区只读展示/配置没有新增删除能力。关系“断联”属于业务有效期事件，不作为可任意撤销的删除；恢复实体不会重连已结束关系。

## 默认策略与配置

- 默认从删除时刻起保留 30 天。回收站内可设置 1–3650 天，作用于当前绑定仓库及其中各模块的回收站内容。同一仓库绑定多个 Agent 时共享保留策略，计划与日志条目仍受各自 Agent 隔离。
- 修改策略先展示确认；缩短期限可能使已有内容在下一次清理时到期，增加期限适用于尚未永久清理的内容。更改需要写入权限、当前 revision、稳定 requestId 和 confirmed。
- 插件注册独立 OpenClaw 原生清理时钟，每小时 UTC 第 17 分钟检查；启动/调度器重建时也核对到期内容，关闭页面不影响清理。无需 Main、Worker、飞书消息或自建业务定时器。没有原生调度器时明确报告未取得后台清理记录，不声称已开启自动清理。
- 到期内容在下一次成功检查时清理，正常情况下延迟不超过一小时；服务停机、调度不可用、在途任务或结果待核验时延后。尚未真正清理的内容仍可恢复，恢复与清理竞争以持久化版本/存储锁为准。

## 删除与恢复边界

### 计划

删除先撤销本地后续触发接纳，再暂停原生计划，记录 deletedAt；保留原计划 ID、授权来源、任务内容、执行快照和历史。删除不取消在途 Worker，不重放业务。普通列表不显示 removed/purged，版本化回收站入口单独读取。

恢复必须属于当前受信 Agent，群请求仍有效且项目仍登记，系统同步配置仍授权；运行中、排队或结果不明时拒绝恢复。恢复到 paused，不立即执行、不自动补跑，启用仍是后续独立操作。旧版本已删除原生 cron 时，可基于保存定义重建暂停的原生投影；原计划逻辑 ID 不变。恢复写入不确定时保留 restorePending，重复 requestId 只返回原回执，不自动重放。

到期清理先核对原生任务归属、执行器和 disabled 状态，并跳过运行/排队/unknown/恢复待核验记录。群计划清除请求正文，保留幂等墓碑和审计；旧 requestId 不能重建已永久清理的计划。系统同步保留最小 purged 墓碑，防止部署配置或重启自动重新创建。

### 人员与来源实体

原数据与回收站标记在实体 SQLite 同一事务中更新。人员保留采集值与人工更正，常规 all/list/lookup 不返回删除项；同步观察不能自动恢复。来源实体仍按来源、revision、证据、关系条件维护，存在有效关联时删除仍须先按规则断联。

恢复核对当前删除版本和原来源，生成新版本，保留来源身份，不重建已结束关系。到期清除业务属性、人员正文与失效关联，仅留来源身份/资源 ID/状态等最小墓碑，阻止后续同来源观察自动重新引入已永久删除资料。事务审计与历史回执独立保留，资源保留期限不代表审计擦除；这不是对源飞书通讯录或外部业务系统的删除。

历史已被旧实现物理删除的人员正文不能凭空恢复。旧的可恢复实体和计划首次接入时获得完整保留期，不推测原删除时间并立即销毁历史内容。

### 仓库日志

“清理来源历史”和旧仓库日志清理入口均把当前选中文件标记为已回收，原文件暂留，常规读取及日志轮转排除这些文件。回收站以清理批次展示，恢复只解除该批次隐藏标记，不覆盖清理后新产生的日志；其他 Agent 的日志和同步执行回执保持独立。

到期仅 unlink 已验证属于该 Agent 的文件名；不跟随符号链接、不删除目标文件。永久清理前更新版本认领，阻止过期恢复；部分 unlink 后失败保留待核验状态，不允许恢复一份不完整的批次。其他插件自行提供的历史清理行为仍由其协议负责，不能假装本地仓库回收站能还原外部来源。

## 管理接口

所有接口基于可信上下文解析 Agent 与绑定目录，拒绝 payload 中任意 Agent、路径、actor 或 shell 参数。

- `projects-recycleBin`，operator.read：`feature`（schedules/entities/logs）、`query`、`limit`（1–100）、`offset`。返回 records/total/nextOffset、settings、最近 cleanup、unavailable。每项包含 provider/id/revision/deletedAt/expiresAt，以及可用的内容摘要。
- `projects-recycleRestore`，operator.write：`provider`（entities/group-schedules/system-schedules/logs）、`id`、`expectedRevision`、`requestId`（最长 120）、`confirmed:true`。不接受直接指定启用、目标群或任务范围。
- `projects-recycleConfigure`，operator.write：`retentionDays`、`expectedRevision`、`requestId`、`confirmed:true`。

query、权限错误和来源不可用不能当作回收站为空。恢复与策略修改使用持久化幂等回执；pending/unknown 须核对列表和审计，不更换请求 ID 自动重放。审计记录删除、恢复、保留期限修改和永久清理，清理回收站不清理审计。

私有元数据位于各现有计划 SQLite，或 Agent Repo 的 `.runtime/recycle-bin/settings.sqlite`、`.runtime/recycled-logs/logs.sqlite` 与实体库，采用 0600 文件和 0700 目录，不进入 Git。只暂存版本、身份和恢复所需数据，不存认证凭证。代码提交与隔离验证不会自动部署或删除线上资源。
