# 工作区任务现场保存与恢复

目标：保留完整任务成果，同时让已停止任务释放池容量；恢复只能回到原独立克隆。实现通过 workspace-pool、workspace-runtime 和 jobs 接入插件；部署状态以实际发布回执为准。只读任务保持默认目录，只有授权写任务进入此流程。

## 身份和持久记录

记录键为 Agent、projectId、jobId、原 assignmentId。记录包含 workspaceId、原绝对路径、各仓库身份、原分支、HEAD、独立保护引用、stash 对象 ID，以及保存阶段。记录写入私有运行目录，不提交 Git。不能使用 stash 列表下标定位。

槽位分配与恢复认领在现有 state.lock 下执行。恢复只能认领记录中的原槽位，并使用当前 assignmentId 作比较交换；返回空闲信息不等于已认领。原槽位正忙时等待，禁止分配其他槽位。

## 保存协议

1. 调度器确认任务及执行进程组终止，没有等待补充、续接或并发回收；先持久记录保存意图及独占认领。
2. 所有仓库先检查身份、Git 操作与索引状态。未结束合并、变基、冲突等不自动保存，明确阻塞。
3. 保存 HEAD 的持久保护引用，防止未推送提交因切换和垃圾回收失去可达性。
4. 用持久日志逐仓保存暂存区、工作树及未跟踪文件；保存操作前后均记录并验证 Git 对象。日志应能识别 stash 创建成功但元数据尚未完成的中断，禁止重复创建或误认他人 stash。
5. 忽略文件不能直接丢弃或共享给下一任务。成果和私有数据必须另行保全并验证；依赖缓存的可复用范围必须显式定义，不能按文件大小猜测。
6. 全部仓库保存完成后标记 saved，清理验证成功后标记 parked 并释放容量。部分成功不释放，保留保存对象及剩余现场，需要核验后恢复，不自动重放不完整步骤。

## 恢复协议

1. 基于原任务授权校验恢复资格；按原槽位排队并独占认领，不新建业务执行。
2. 校验路径、真实 Git 根、远端和全部保护对象；全部通过后才进入 restoring。
3. 恢复原 HEAD/分支，再使用精确对象执行 stash apply --index；逐仓恢复其他已保存文件。
4. 冲突或部分恢复中断保留对象和现场，标记 recovery_required。不能自动重复 apply。完整恢复已写入日志但回执丢失时，重新核验全部文件和 Git 状态后补回执，不再应用 stash。
5. 全部仓库验证完成后才允许 Worker 启动。保存引用先保留，另行确认安全结算后回收，禁止立即 pop/drop。

## 集成范围

- workspace-pool：检查点记录、原槽位认领、保存/恢复状态与失败保护。
- workspace-runtime：恢复既有任务快照，禁止再次将逻辑路径重复映射。
- jobs：保存/恢复期间不启动 Worker；原任务排队恢复；保留来源与原执行快照；终态结算和检查点存续分开。
- session-deletion：有检查点时禁止删除唯一恢复索引。
- 管理页面显示保存中、恢复中及异常保留；状态接口通过 waiting_original_workspace 区分等待原槽位与普通容量不足。
- Worker/Main 技能：说明原任务恢复、原槽位约束和无权手工 stash/drop/清理运行目录。

## 必须通过的验证

临时仓库覆盖：暂存与未暂存同时存在、未跟踪与忽略成果、未推送提交、多独立仓库、原槽位被其他任务占用、多个恢复请求竞争、保存/恢复各步骤中断、磁盘或 Git 错误、冲突、身份变化、失效授权、旧任务迟到事件、正在运行任务拒绝保存。验证保存前后文件内容和 Git 对象可达性，不只检查状态字段。

实施不得在真实 XGJ 工作区试验。现有扩容措施与本方案分开，不证明检查点功能已上线。
