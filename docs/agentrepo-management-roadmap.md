# AgentRepo 管理中心规划

AgentRepo 是当前 Agent 的长期工作区管理入口，跨其所有会话使用；人员库是其中一个模块。每个 Agent 的资料、执行记录与配置独立。切换会话不改变管理范围，切换 Agent 则重新读取全部数据。

## 已实现的基础

- 概览：真实项目数、人员数、同步计划与保留的异常记录；显示数据读取失败、未提交登记、缺少邮箱和待核验账号关联，提供对应模块入口。
- 项目与技能：登记项目、角色和项目范围的技能、子代理定义及来源检查。
- Worker 任务：当前 Agent 跨会话统计、项目/状态/文本筛选、分页摘要与原任务详情定位，状态由 agent-worker 提供。
- 人员库：聊天采集、符合当前群与 Agent 绑定规则的飞书群同步、搜索筛选、人工更正与账号关联。
- 定时任务：仓库同步系统任务的计划、执行历史与日志，只读。
- 仓库日志：按 Agent 查询、复制、下载及有确认保护的清空。

概览不是远程健康探测，空日志也不等于所有功能正常；未获取的姓名、邮箱与部门仍显示未知。统计不将项目候选技能当作已激活技能。

## 建议的后续顺序

| 优先级 | 能力 | 用户价值 | 首个交付范围与验收 |
| --- | --- | --- | --- |
| P1 | 工作区检查 | 直接回答“为什么当前 Agent 不能工作” | 按项目登记、仓库身份、未提交改动、技能来源和插件绑定展示检查项；每项有证据时间、阻塞原因及定位入口；只读检查，不自动修复。 |
| P1 | 项目登记管理 | 无需改 JSON 即可接入项目 | 选择已有本地仓库、验证 origin/分支/路径，预览登记差异并确认保存；登记提交和推送独立显示结果；保留用户已有改动，禁止覆盖和强推。 |
| P1 | 人员资料治理 | 让联系人可查询、可维护、可信 | 展示资料来源、最后采集时间、人工覆盖字段和变更记录；支持按权限刷新单人资料；同名、同邮箱只提示候选，不自动合并身份。 |
| P2 | 知识与记忆管理 | 看清 Agent 长期保存了什么 | 浏览已有记忆与规则文件、来源和更新时间，搜索并预览修改差异；保存前明确确认；不把全部聊天自动归档为记忆，不混入其他 Agent 资料。 |
| P2 | 操作与任务中心 | 看清正在执行什么、失败在哪 | 汇总同一 Agent 的手动同步和定时任务；稳定的任务 ID、进度、日志及历史；区分支持取消与不可取消阶段；重试必须先重新预检。 |
| P2 | 配置与能力检查 | 区分“已安装、已启用、当前 Agent 可用” | 查看绑定、版本兼容、技能范围与模型认证状态；只展示认证是否可用，不读取或导出密钥；修复建议先给出具体差异。 |
| P3 | 全局活动记录 | 管理动作可追溯 | 记录操作者、目标、时间、动作与结果；筛选与脱敏导出；不保存聊天正文或凭证；明确保留时间与清理机制。 |

先做工作区检查、项目登记管理和人员资料治理，可以把管理台从查看工具推进到日常管理工具。任务中心需要与现有执行队列和调度语义对齐，避免只是增加“重试”“取消”按钮却无法兑现行为。

## 导航与交互约定

根侧栏始终只有 AgentRepo 入口。页面内按“概览、项目与技能、Worker 任务、人员库、定时任务、仓库日志”组织；新增能力优先归入现有模块，达到独立管理范围时再扩展。会话侧栏保留快捷查看功能，完整操作在管理中心完成。

每次读取显示载入、空数据、权限不足与失败状态。写操作展示明确目标与影响；可恢复的修改保留撤回方案。敏感操作沿用宿主权限，不以“全局管理”为理由扩大跨 Agent 或跨群访问。

飞书 openId 属于对应应用作用域，跨应用或跨渠道身份必须显式核验关联。统一人员库统一的是当前 Agent 对人员的管理视图，不是把各来源 ID 混为一个无来源的用户编号。
